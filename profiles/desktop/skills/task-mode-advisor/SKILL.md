# 任务执行组合顾问（Task Mode Advisor）

本技能的目标：**在动手前 30 秒，用一张评分表把任务复杂度量化，然后给出一个明确的执行组合建议**，避免两种常见浪费——简单任务开 `max` 思考（慢且贵）、复杂任务用错模式（探索型任务开 PTC 会丢失中间过程可见性）。

---

## 第一部分：复杂度分级（先做这个，再谈配置）

对收到的任务按以下 5 个维度评分，各 1-3 分：

| 维度 | 1 分（低） | 2 分（中） | 3 分（高） |
|---|---|---|---|
| **范围** | 单文件、单函数 | 2-5 个文件、一个小功能 | 跨模块、多子系统、架构级 |
| **风险** | 无状态、可回退 | 有状态变更、需要测试 | 数据迁移、并发、安全、生产影响 |
| **探索性** | 步骤完全确定 | 部分步骤需根据中间结果决策 | 需反复读输出、排查、试错 |
| **编排量** | 0-1 次工具调用 | 2-5 次顺序调用 | 长序列、循环、条件分支 |
| **自主长度** | 单轮完成 | 数轮，需用户少量确认 | 多阶段长程任务 |

**总分 5-15 分 → 定级：**

| 等级 | 总分 | 典型例子 |
|---|---|---|
| **L0 简单** | 5-6 | 回答事实问题、改一行配置、起一个命令、单文件小改 |
| **L1 日常** | 7-8 | 修一个 bug、单文件函数、写注释/文档、跑测试 |
| **L2 中等** | 9-11 | 小功能、跨 2-3 文件、常规重构、写测试套件 |
| **L3 复杂** | 12-13 | 跨模块重构、架构调整、算法/并发/性能难题、安全审计、大 diff 评审 |
| **L4 长程自主** | 14-15 | 多阶段自动化任务（配合目标/工作流/多轮迭代） |

> 附加判断：若任务属**批量机械修改**（同样模式改 N 个文件、批量重命名、批量迁移），在定级基础上标注 `+batch` 标记——这直接指向 PTC 模式。

## 第二部分：模式清单（agent preset）

| 模式 | preset id | 能力面 | 优势 | 劣势 | 适合 |
|---|---|---|---|---|---|
| **标准模式** | `standard` | 全工具：文件、Shell、文件/网页检索、Skills、计划、目标、子代理、工作流 | 万能、探索可见 | 提示词长、token 略多 | **默认选择**；所有说不清需求的任务 |
| **PTC 模式** | `code` | = 标准，但工具以 Code Mode SDK 呈现：只有 `run_code` 可直呼，模型写一个 TypeScript 程序批量组合操作 | 5 次往返变 1 次；中间值不进上下文；省 token、快 | 只回传「程序日志+返回值」，中间过程不可见；批量大动作粒度粗、难以逐步审查 | **批量机械修改**（`+batch` 标记）、确定性多步流水线、长序列工具调用 |
| **极简模式** | `minimal` | 仅 `bash` + `str_replace_editor` | 提示词最短、最省 token、模型不易过度思考 | 无检索、无子代理等 | L0 超小改动、临时脚本 |
| **创造模式** | `cordis` | = 标准 + 运行时检查、插件实验、preset 创作指导 | 制作/调试自定义 preset 的唯一正确工具 | 面向 preset 作者 | 创建/调试自定义 agent preset |
| **Code Review** | `code-review` | = 标准，但 persona 为资深审查者，默认只读 | 评审报告结构化、不污染代码 | **不写代码**（review-only） | 评审 PR/diff/文件/目录 |

**辅助状态（非 preset，任何模式下可用）：**

- **计划模式（plan mode）**：`/plan` 进入、`/plan off` 退出、`exit_plan_mode` 提交计划。L2+ 任务先规划再动手的标配；大改之前先出计划给用户确认。
- **目标（goal）**：同会话长程目标 + 自动续行。L4 任务用它承载多轮自主推进。
- **工作流（workflow）**：大批量并行 fan-out（审计多个文件、多角度研究）。任务可拆成 N 个独立子任务时用。
- **子代理（subagent）**：独立、自包含的委托；后台默认运行。1-2 个独立子任务时用。

## 第三部分：思考强度（推理等级）

**deepseek-official 提供方（当前默认）**：仅三档（`dsh-llm-deepseek` 适配器）：

| 档位 | 行为 | 成本/延迟 | 何时用 |
|---|---|---|---|
| `off` | 关闭思考（`thinking: disabled`） | 最低 | L0 简单任务、纯执行 |
| `high` | 开启思考（默认档） | 中 | L1-L2 日常，**当前全局默认** |
| `max` | 最深思考 | 高 | L3 复杂、L4 长程、评审、疑难 |

**pi-ai 提供方（token-plan 网关）**：按模型声明最多七档 `off / minimal / low / medium / high / xhigh / max`，映射关系同上表（minimal/low ≈ off~high 之间；xhigh ≈ max 附近的档位）。选择器只显示该模型实际声明的档位。

**经验法则**：思考深度应随复杂度**单调不减**——但不必全程 `max`。默认 `high`，仅在任务呈现以下信号时升 `max`：
- 需要长时间推理链（算法、并发、安全分析）
- 模型在 `high` 下反复出错、绕圈、遗漏约束
- 任务是一次性的高质量输出（评审、方案设计）

## 第四部分：推荐逻辑（复杂度 → 组合）

### 决策表（主推荐）

| 定级 | 推荐模式 | 推荐思考强度 | 辅助策略 |
|---|---|---|---|
| **L0 简单** | 极简 或 标准 | `off` | 无 |
| **L1 日常** | 标准 | `high` | 无 |
| **L2 中等** | 标准 | `high`（必要时 `max`） | 建议先 `/plan` |
| **L2 + batch** | **PTC** | `high` | 无 |
| **L3 复杂** | 标准 | `max` | 必须 `/plan` |
| **L3 评审型** | Code Review | `max` | 只读执行 |
| **L4 长程自主** | 标准 | `max` | 建 goal，必要时 workflow fan-out |

### 反例（明确不要这么配）

- ❌ L0/L1 任务用 `max` —— 浪费 token 与延迟（这是最常见的错误配置）。
- ❌ 探索型任务（排查、试错、需要看中间结果）用 **PTC** —— `run_code` 只回传程序日志+返回值，中间工具输出不可见。
- ❌ 需要逐步人工审查的长流程用 **PTC** —— 多步合成一个大动作，审查粒度变粗。
- ❌ 日常写代码默认用 Code Review —— 它默认只读、不修改代码。
- ❌ 简单任务用极简模式以外的重模式没必要，但无害（提示词更长而已）。

### 判断树（快速版）

```
任务是否有批量机械模式（同样的操作 × N 个文件）？
├─ 是 → PTC 模式 + high
└─ 否 → 任务是否需要探索/排查/看中间结果？
    ├─ 是 → 标准模式 + high~max（探索型别用 PTC）
    └─ 否 → 按复杂度表：L0→off，L1-L2→high，L3-L4→max
```

## 第五部分：输出格式（建议的交付物）

接到任务并完成评估后，按以下模板输出（**简洁，3-5 行**）：

```
📋 复杂度评估：L{n}（范围 X/风险 Y/探索 Z/编排 W/自主 V = 总分 N）

▶ 建议组合：{模式} + {思考强度}{ + 辅助策略}
   理由：一句话（为什么这个组合匹配任务性质）

⚠ 备选/注意：{什么情况下升级到 max / 换 PTC / 先计划模式}
```

示例：

```
📋 复杂度评估：L3（范围 3/风险 2/探索 3/编排 2/自主 2 = 12）

▶ 建议组合：标准模式 + max 思考强度 + 先进入计划模式
   理由：跨模块重构需要长时间推理链，且需先规划确认再动手。

⚠ 注意：若实施中出现批量同类修改（如 20 个文件同模式），中途可换 PTC 模式；但当前会话已产出内容则无法换 preset，需新建会话。
```

## 第六部分：环境事实与注意事项（写死的事实，勿臆测）

- 当前机器默认配置（`C:\Users\wangh\.dsh\settings.yaml`）：`agent-default-model` = deepseek-official / deepseek-v4-flash / `reasoningEffort: high`；`agent-presets.default` = `standard`。
- 可用模式（preset id）：`standard`（标准）、`code`（PTC）、`minimal`（极简）、`cordis`（创造）、`code-review`（Code Review，用户自建）。
- **模式切换限制**：只有「尚未产出任何内容」的空白会话可以切换 preset（`recompose` 限制）；已产内容的会话锁死在其创建时的 preset。改 `settings.yaml` 的默认只影响**此后创建**的会话。
- **思考强度随时可切**：模型选择器 → 「推理等级」面板，对下一个请求立即生效；无需重启。
- 若模型是 pi-ai 提供方（token-plan 网关），档位集合按模型声明（最多七档）；`off` 在部分模型上可能「选了也关不掉」（该能力不可用时选择器不显示）。
- 会话标题生成强制 `thinking: disabled`（`session-title` 用途），与用户选择无关，属正常行为。
